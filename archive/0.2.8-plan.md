# 0.2.8 — Catalog split by lineage

The catalog grows one branch at a time, so its records are stored one lineage per file. `js/catalog.js` remains the composer: it owns the generation headings, family colors and glyphs, the instrument reference table and the search, numbering and lookup methods. Seven lineage files own the records themselves, in the same order the archive has always shown them.

| Lineage file | Order | Records |
|---|---|---|
| `js/lineages/blues.js` | 001 | Blues |
| `js/lineages/jazz.js` | 002–004, 013 | Jazz, Swing, Bebop, Jazz fusion |
| `js/lineages/rhythm.js` | 005–007, 011, 012, 015, 016, 017, 019, 020, 025, 028, 029 | R&B, Soul, Funk, Disco, Hip-hop, House, Techno, Drum and bass, Breakbeat hardcore, Jungle, Motown, Atmospheric DnB, Trip-hop |

## File numbers, not file order

Each record carries `file`, its archive slot. A new record is appended to its lineage with the next free number; nothing moves and no earlier file changes number. The composer sorts the published records by `file`, so reading order, profile numbers (`FILE / 041`) and the index stay identical to a single-list catalog.

A lineage owns one family and its own records only. Cross-lineage relationships stay data: `parent` and `influences` use genre ids and resolve after publishing. Adding a branch to an existing genre touches one lineage file. A new family needs a new lineage file, plus its color, glyph and label in the composer.

## Publication

`index.html` loads the composer, then the seven lineage files in archive-family order, then the feature scripts and `js/main.js`. Lineage files are plain data with a common-js guard, so they read nothing at definition time. `bootAtlas` registers each lineage with `genreCatalog.addLineage` and calls `publish()` before any feature initialises. Under Node the composer publishes at require time with the same registry.

The runtime stays build-free and offline: classic script tags, no modules, no fetches on load. Search normalisation, the rhythm studies and the synthesized patterns are unchanged.

## Acceptance and manual pass

1. `node --test experiments/*.test.cjs` — all lineage files declare every record once, file numbers stay `001`–`043`, ordering in the footer and index matches, and the page never reaches the features before publishing. `node --check` each touched file.
2. On a `file://` load, the map draws 43 cards over nine generation columns and the footer reads `43 genres / 6 roots`. Open a card from each lineage file, including Blues (001), Motown (025), Mento (032) and Cha-cha-chá (043), and confirm the file numbers.
3. Filter Blues, R&B, Rock, Jamaican, Country and Afro-Cuban in turn: each hides unrelated cards, keeps the ancestors and opens the family's first record. Search `bristol sound`, `liquid dnb` and `La enganadora` to confirm the records still resolve across files.
